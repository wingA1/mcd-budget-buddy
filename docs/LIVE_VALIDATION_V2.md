日期：2026-10-23，北京时间10:09—10:13。环境：ChatGPT Work，Python标准库客户端。
固定测试门店：麦当劳广州今日广场餐厅（1400011），到店自取。不代表用户当前位置或实际点餐意图。

## 实际执行链路

`initialize → now-time-info → query-meals → query-store-coupons → query-meal-detail → calculate-price → validate_quote → rank → Markdown报告`

新流程中，`query-meals`、`query-store-coupons`各调用一次，详情调用三次，完整购物篮试算三次，全部业务`success=true, code=200`。开发前另查询了同一套餐详情，确认默认选项。

输入：2人、总预算50元、每人至少一份饮料。主食候选指定为吉士蛋麦满分5888与粥王系列精选套餐9900005470，饮料为优品豆浆1088。随后程序根据真实详情构建三种组合。

套餐9900005470的当时默认组成：雪菜脆笋鸡肉粥×1、脆香油条×1、脆薯饼×1，**不含饮料**。因此另加两杯豆浆；程序没有重复计算套餐内饮料。每个round的ID、默认商品code及quantity均来自真实详情，没有将内部选项当作顶层独立商品。

## 报价校验

- 业务成功状态。
- 请求顶层编码在本店菜单内。
- 返回顶层商品编码与数量与请求一致。
- `productList`逐项`subtotal`之和等于`productPrice`。
- `price`等于商品现价加已返回的配送/包装/餐具费用；本轮总价均与商品小计无差额。
- 以分为整数运算，再用Decimal转换为元。
- 排序器再次检查归一化价格、商品编码与数量，不能仅凭`quote_accepted=true`进入结果。

原始业务响应中的金额分别为3900、4450、5000分。对应脱敏请求和响应见 `examples/verified-history.json`。保留商品编码、默认特制、套餐round、数量及金额；移除traceId和账号相关信息。较早09:45的两个单品案例也收录其中，明确为不同采集时段。

## 复现

无需Token，历史回放：

```bash
python scripts/rank_quotes.py examples/verified-history.json --replay
python -m unittest discover -s tests -v
```

`--replay`按证据采集时刻检查历史记录，输出标识为`historical-replay-not-live`。不代表当前报价；实时模式仍执行15分钟防陈旧策略。

离线反例使用**合成数据**：接口漏返一件商品、金额不一致、归一化字段被篡改、只有核验标记没有原始证据、买卡条件价、缺少默认选项等。这些反例不是本次门店实际发生的故障。

## 边界

本次验收覆盖到店自取、默认套餐选项、独立饮料和三种组合。未验收外送、券抵扣、自定义套餐换项或全菜单最优搜索；程序仅生成有限候选。菜单和试算成功也不构成库存保证。口味分类采用公开餐品名的保守启发式，不提供过敏或营养保证。
